# 010 · Codex 环境与工具链审计

**状态**：✅ 已验证（本地审计报告） ｜ 📋 原始清单原文不上传

> 来源：`codex-environment-audit-20261115/审计报告.md`（本地文件，不进本仓库）。以下只写结论与量级，不上传逐项清单原文。

## 目标

搞清本机 Codex 的 Skills、MCP、插件、Token 用量与工具效率现状，区分哪些是已证实、哪些只是高概率或潜力。

## 环境

- Windows 11 Home build 26200；Codex MSIX 26.1111.2228.0；内置 CLI 0.169.0-alpha.11.1。
- 审计日期 2026-11-15（Asia/Shanghai），覆盖桌面聊天、本机 CLI、配置中 10 个受信任工作区。

## 实际步骤

1. 逐项登记安装版本、配置条目与工具目录，写入 `inventory.json`。
2. 独立启动 MCP 并枚举工具，做一次真实 GUI 操作闭环。
3. 从本地 rollout 汇总 Token 口径，交叉核对累计变化次数。
4. 统计 Skills / MCP / 插件数量、重复与冲突。
5. 区分「已证实 / 高概率 / 仅有潜力」三档结论。

## 实际结果

| 项 | 实测 |
| --- | --- |
| Windows-MCP 0.8.9 | 安装注册完成；独立启动枚举 10 个 GUI 工具；启动并列工具 10.28 秒 |
| GUI 闭环 | 状态读取 → 打开记事本 → 输入 → 精确回读 → 撤销 → 关闭；测试后 0 残留进程、0 同名开机任务 |
| Skills | 磁盘 101 份；三个范围分别 58 / 52 / 14；去重后 80 份；加载错误 0；1 组同功能双版本 |
| MCP | 用户配置 2→3；全局 6 + 项目 1 = 7；0 重名；启用项均能返回工具目录 |
| Token 口径 | 48 个 rollout 文件（47 个有效）；按采样口径汇总累计输入 / 缓存输入 / 输出，见审计报告 |
| 工具效率 | 同一任务内 107 次相同参数轮询；最大单条工具结果约 53.4 MB |
| GUI 输出对比 | 纯窗口状态 442 字节；带 UI 树 43,847 字节 |

## 失败经验

- 系统 Python 缺某个依赖的 Windows 轮子 → 改用 uv 管理的隔离 Python 环境，按发布标签锁文件固定版本。
- 提示词优化器曾返回与原任务无关的结果 → 明确同一任务跨层合计优化一次；AE 桥接 Skill 依赖缺失 → 加入可用性判断与原生脚本回退。
- 审计结论刻意分级：重复轮询是否必要、完整工具套件是否常态浪费，现有日志不足以判断，标为「高概率 / 仅有潜力」，不写成节省。
- 验收工具的 PowerShell 5.1 与生产 PowerShell 7 不同，5.1 的 API 缺失不是生产限制。

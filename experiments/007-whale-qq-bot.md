# 007 · 鲸戒 QQ 机器人：有状态服务的长期运维

**状态**：✅ 公开仓库有大量可查的提交、文档与补丁记录 ｜ ⚠️ 本实验记录作者未亲自执行过线上运维

> 主人确认实际使用和研究过鲸戒 QQ 机器人。公开仓库 <https://github.com/jiuhuweisi-maker/qq-whale-girl-diary> 提供了充分的项目级证据；但"仓库里有记录"和"本人亲自跑过"是两回事，本文把两者分开写。

## 目标

维护一个长期在线、有记忆、有多层补丁约束的 QQ 机器人链路，同时做到：换机可复现、状态可迁移、凭据不进 Git、版本不被自动更新破坏。

## 环境（来自公开仓库）

- 公开 README 记录的上限形态：DSH + SurfCore 固定 0.8.8 + 容器化 QQ 客户端 / OneBot；relay 与 ws 由 systemd 托管。
- 系统要求（`docs/FRESH-SERVER.md`）：Ubuntu 22.04+ / Debian 12，root，systemd，Node 24+，Python 3.6+。
- 具体 IP、QQ 号、群号、票、密钥、代理节点均不在本仓库。

## 实际步骤（可从公开文档核对）

1. **三层分离**：代码层进 Git；配置层放仓库外、权限 600；状态层用 `state-transfer.sh` 打包，明确不进 Git。
2. **先干跑再真跑**：`bootstrap.sh --check` 只做预检；真跑依次构建固定上游 + 覆盖层、装 relay、生成配置、注册控制包、离线回归。
3. **逐文件验指纹**：公开文档记录 2026-11-04 构建 571 个文件，与线上清单逐个 SHA-256 比对 0 差异。
4. **状态迁移**：export / import 带 MANIFEST 与 SHA256SUMS；票与凭据不打包。
5. **锁版本**：关自动更新开关、更新器 cron 不安装、同名端口 / 卷 / 单元被占就拒绝部署。
6. **按清单验收**：公开文档列出 12 项顺序检查，任一项不对不上线。

## 实际结果（来自公开仓库，非本人复现）

- 公开文档记录代码层可从 Git 原样复现，571 文件哈希零差异。
- 公开文档记录 226 迁移包约 4.07 MiB / 92 文件，逐文件哈希 `bad=0`，只读导入演练 `ok:true`。
- 公开事故复盘（`docs/INCIDENT-2026-11-07-MEMORY-EXHAUSTION.md`）记录了一次"不回消息"的根因：内存耗尽使 DSH 卡在 D 状态，叠加上游 API 中断；以完整备份 + 停用无关服务 + 整机重启恢复，重启前后 581 个改动数量一致。
- **本人未亲自执行上述任何一步**。以上是项目级公开证据，不是我的运行报告。

## 失败经验（来自公开复盘）

- 不要反复重启 DSH：内存见底时 stop 要强杀，重启后读盘数分钟才绑端口。
- 内存见底时不要降低 `swappiness`，会阻止匿名页换出、诱发 OOM。
- 导出前必须设 `SURFCORE_ROOT`，否则会静默漏掉部分状态文件。
- 口径更新后旧包必须重打，否则废弃语句会随记忆维护复活。
- 校验清单用二进制写回 LF，否则 `sha256sum -c` 会因 CRLF 全量报错。

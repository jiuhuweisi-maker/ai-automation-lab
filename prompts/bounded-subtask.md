# 模板：界定清楚的子任务

> 方括号内容全部替换；不要粘贴真实凭据或私有路径。

```text
任务标识：[短 ID]
目标：[一句话说明要做到什么；只写一个目标]

允许修改的文件（精确路径，逐条列出）：
- [文件路径 1]
- [文件路径 2]

禁止事项：
- 不要修改白名单之外的文件
- 不要执行 shell 命令、访问 URL 或调用外部工具
- 不要提交、推送或部署
- 不要读取用户目录、密钥文件或无关项目

验收条件：
- [可机械检查的条件，例如：某测试通过 / 某字段存在]
- [人工可核对的条件，例如：输出与输入逐条对应]

输出要求：
- 给出改动摘要、逐文件 diff、测试结果
- 无法确认的地方写"未验证"，不要推测
```

## 真实记录：额度接手提示（脱敏）

下面这段来自 2026-11-14 的派发实测，数值已换成占位符。它说明提示词首段长什么样——**不是**一个凭空设计的示例。

```text
HANDOFF NOTICE (local Codex quota state): 【Copilot 主动接手】Codex 主窗口额度剩余 <N>%，已按既有授权转为 Copilot 接手。
Only inspect or edit these exact files:
- <精确白名单文件>
<原任务描述>
```

实测要点：

- 落盘的 `copilot-prompt.txt` 首行就是上面这条通知，全文 991 字节，中文按 UTF-8 无损。
- 白名单与原始任务描述都保留，隔离工作树里的执行方不需要读工作区外的文件。
- 视图 / 编辑 / 补丁之外的工具被禁用；没有 shell、URL、MCP 和二次委派。
- 真实派发共 5 次，其中一次端到端任务用了 **0.14 AI Credits**（单次软上限 30），只改白名单里的一个文件。

## 为什么这样写

- **精确文件清单**让隔离环境能只带必要文件，也方便事后核对。
- **禁止事项**显式列出，比依赖模型的"常识"可靠。
- **验收条件**把"差不多完成"变成可以判断的命题。
- **未验证要明说**，避免模型用流畅的语言掩盖不确定。
- **首段接手提示**让执行方在不接触宿主环境的情况下知道当前额度状态与授权边界。

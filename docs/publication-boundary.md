# 公开边界与脱敏规则

这份文档是本仓库的发布纪律。新增任何文件前先过一遍这里。

## 可以公开

- 实验的目标、方法、判断依据、失败结论和改进方向。
- 已经验证过的**结论与数据**，前提是数据本身不暴露基础设施位置或身份。
- 脱敏后的配置骨架、目录结构、流程图、提示词模板。
- 与公开仓库、公开文档之间的链接。

## 不公开

| 类别 | 例子 | 处理方式 |
| --- | --- | --- |
| 密钥与凭据 | API Key、Token、密码、Cookie、SSH 私钥、OAuth refresh token | 完全排除，不用占位符"留个样子" |
| 服务器信息 | 公网 IP、域名解析细节、SSH 端口、登录票据、代理节点 | 换成 `<SERVER_IP>` 等占位符，或直接省略 |
| 私有数据 | 私人记忆、账本、收藏、聊天记录、角色设定、图片原图 | 不进仓库，只描述结构 |
| 本地私有路径 | 含用户名或私有目录的绝对路径 | 换成相对路径或 `<PRIVATE_PATH>` |
| 未验证功能 | 写完但没跑通、只在计划里的能力 | 明确标为 ⚠️ 或 📋，不写成已实现 |

## 脱敏约定

- 主机名 / IP：`<SERVER_IP>`、`<HOSTNAME>`
- 本地私有路径：`<PRIVATE_PATH>`
- 任何疑似凭据：直接删除整行，不保留部分片段
- 版本号、工具名、开源仓库名可以保留——这些不是秘密

## 发布前自检

```bash
python scripts/check_repo_hygiene.py
```

脚本会扫描工作区里的文本文件，报告疑似私钥头部、常见密钥前缀、IP 地址、凭据赋值和本机绝对路径。**它是辅助工具，不是保证**——脚本跑完仍需人工看一遍 `git diff --cached`。

如果扫描结果有命中：先判断是真命中还是文档里的规则说明。规则说明本身若包含示例模式，应使用不完整的占位写法，避免误报。

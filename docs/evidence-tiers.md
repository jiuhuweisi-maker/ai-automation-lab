# 工具与证据矩阵（补充）

主规则见 [状态与证据纪律](status-and-evidence.md)：**已验证 / 进行中 / 待整理**。本文补充一张按工具对照的矩阵，说明"经历"与"证据"如何分别记。

## 为什么需要这张表

- **没找到日志，不代表实验没发生。** 主人确认过的经历照样算真实。
- **用过，不等于验证过结果。** 没有可核对记录的方向，只标待整理，不写数字。
- **A 工具的记录不写成 B 工具的成果。**

| --- | --- | --- | --- |
| Codex | ✅ | 任务路由、额度守护、全局规则文件、环境审计 | ✅ 已验证 |
| Copilot CLI | ✅ | 5 次真实派发的日志与 diff | ✅ 已验证（一个案例） |

## 读法

- "主人确认经历"是事实，不因证据缺失而否定。
- "状态"描述的是**证据整理程度**，不是经历是否发生。
- 一个工具可以同时有已验证的部分和待整理的部分。例如 WorkBuddy 有本仓库的实际工作，也有与 Codex 协作待补的细节。

## 关于 Codex + Copilot CLI

那 5 次派发是**一个已验证案例**，属于方向 1 的一部分，不是整个实验室的全部，也不代表 Codex + WorkBuddy 的协作方式。

# 状态定义与证据纪律

这是本仓库的阅读规则。三句话先说清楚：

1. **没找到日志，不代表实验没发生。** 主人确认用过，就记为真实经历。
2. **用过，不等于验证过结果。** 没有可核对记录的结果不写数字、不写结论。
3. **A 工具的记录不写成 B 工具的成果。** 尤其不要把 Codex + Copilot CLI 的案例冒充 Codex + WorkBuddy。

## 三种状态

| 状态 | 含义 | 可以写什么 |
| --- | --- | --- |
| ✅ **已验证** | 有公开仓库提交 / 文档 / 本地日志可直接核对 | 具体步骤、数值、失败经验、证据出处 |
| 🔄 **进行中** | 主人确认在持续使用，有部分证据，但尚未整理完整 | 工具清单、方向、已确认的结论；细节标待补 |
| 📋 **待整理** | 主人确认使用 / 研究过，但没有任何可公开引用的记录 | 只写入口和目标，不编造任何结果 |

状态是**按证据给的方向级标签**，不是对主人经历的否定。📋 待整理的意思是"记录还没整理"，不是"还没做过"。

## 证据与经历分开记

每个方向都可以同时有：

- **经历**：主人确认实际使用过（来源：主人陈述）。
- **证据**：公开仓库、提交历史、本地日志（来源：可核对文件）。

两者缺一不影响另一方成立。表格里会分别标出。

## 公开边界

不公开：API Key、Token、密码、Cookie、SSH 私钥、代理节点、服务器地址、QQ 号 / 群号、私人记忆、账本、角色原图、本地私有路径。

公开仓库已有的事实可以引用，但凭据和账号信息不复制进本仓库。详见 [公开边界](publication-boundary.md)。

## 本仓库的定位

这是**个人 AI 自动化与多模型实践中心**，覆盖九大方向，不局限于当前机器上有日志的项目。日志只是证据来源之一，不是仓库范围的定义。

# 工作流：隔离派发小任务

来源：[实验 003](../experiments/003-multi-agent-collaboration.md)。状态：✅ 准备阶段端到端演练通过；真实派发未发起。

## 前置条件

- 任务小到可以一次审完，且能写清楚要改哪些文件。
- 源工作树干净。不干净就停止，禁止 stash / reset / clean 覆盖用户改动。
- 只从当前工作区、Git 根、显式路径或精确登记的项目 ID 解析项目；不从父目录猜仓库。

## 准备

1. 创建 detached sparse worktree，只包含明确列入白名单的文件。
2. 非 Git 工作区：只复制白名单文件到临时 Git 基线，并核对源哈希。
3. 写提示词文件：一个任务、一条提示词、一张精确的文件清单。

## 派发

- 只给 `view` / `edit` / `apply_patch`；禁 shell、URL、MCP 和二次委派。
- 一次一个任务，设 Credits 软上限和超时。
- 不自动重试，不用 `--allow-all` / `--yolo` / `--fleet` 一类开关。
- 不把用户目录、系统目录、密钥文件或无关项目传给 Agent。
- 解释器和编码要统一：统一使用 PowerShell 7 与 UTF-8，避免 5.1 的 API 缺失和中文乱码。

## 审查与集成

1. 保留 stdout、stderr、退出码、diff、测试结果和用量记录。
2. 主 Agent 审查 diff，跑测试。
3. 确认源工作树仍在记录的基线上，才集成。
4. 不自动提交、不自动部署。
5. 遇到交互式登录、验证码或超出授权的动作，暂停并交还给人。

## 一句话总结

**小任务外包，架构与最终审查留下；隔离、白名单、可回滚，三样缺一不可。**
